Capabilities as an indexed table: `[01]` index left, service name at ~2rem centre-left, description in small monospace right, hairline rule between each row.

The transferable rule: **a list of capabilities is better as a table with rules than as a card grid.** Rows are compact, comparable, and scannable in one vertical pass; cards force the eye to zig-zag and inflate five items into a full screen of boxes. Use cards when items have images, rows when they are text.

Within each row the three columns carry three registers: index (mono, tiny), name (sans, large), description (mono, tiny). **Two extreme type sizes and no intermediate steps** is the same system used across this site — it makes hierarchy unambiguous at a glance.

Above the table, reference images are scattered at varied sizes and vertical offsets rather than aligned into a strip. The contrast between a loose collage and a strict table is what gives the section its structure — one ordered element and one disordered element, neither competing for the same job.

Whole section on saturated orange. Black type on orange holds contrast; white would not.
