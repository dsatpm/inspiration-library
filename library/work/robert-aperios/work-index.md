Each project is one full-width row split into three columns: client mark left, image centre, metadata and description right. Hairline rules above and below make the row a band.

The transferable rule: **a three-column project row gives a portfolio a consistent scannable rhythm that a masonry grid cannot.** Every project exposes the same four facts in the same positions — mark, visual, client + project type, description. The reader learns the pattern once and can then skim twenty projects. Masonry grids force re-reading the layout at every item.

The mockup is a **contextual photograph** — the site shown on a display on a real desk with a lamp and books — not a flat browser frame. Environmental mockups imply the work shipped; flat frames imply a concept. Pick according to what you are claiming.

Description is monospace uppercase at ~0.7rem, deliberately dense, describing the *system* built rather than the visual ("custom page templates, a flexible component setup, lightweight scripts"). For a developer portfolio, describing architecture rather than appearance is the differentiator.

`VIEW PROJECT` is a small bordered chip in the left column — consistently placed, never competing with the image.
